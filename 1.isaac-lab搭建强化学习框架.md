```python
@configclass
class LocomotionVelocityRoughEnvCfg(ManagerBasedRLEnvCfg):
    """Configuration for the locomotion velocity-tracking environment."""

    # Scene settings
    scene: MySceneCfg = MySceneCfg(num_envs=4096, env_spacing=2.5)
    # Basic settings
    observations: ObservationsCfg = ObservationsCfg()
    actions: ActionsCfg = ActionsCfg()
    commands: CommandsCfg = CommandsCfg()
    # MDP settings
    rewards: RewardsCfg = RewardsCfg()
    terminations: TerminationsCfg = TerminationsCfg()
    events: EventCfg = EventCfg()
    curriculum: CurriculumCfg = CurriculumCfg()

    def __post_init__(self):
        """Post initialization."""
        # general settings
        self.decimation = 4
        self.episode_length_s = 20.0
        # simulation settings
        self.sim.dt = 0.005
        self.sim.render_interval = self.decimation
        self.sim.physics_material = self.scene.terrain.physics_material
        self.sim.physx.gpu_max_rigid_patch_count = 10 * 2**15
        # update sensor update periods
        # we tick all the sensors based on the smallest update period (physics update period)
        if self.scene.height_scanner is not None:
            self.scene.height_scanner.update_period = self.decimation * self.sim.dt
        if self.scene.contact_forces is not None:
            self.scene.contact_forces.update_period = self.sim.dt

        # check if terrain levels curriculum is enabled - if so, enable curriculum for terrain generator
        # this generates terrains with increasing difficulty and is useful for training
        if getattr(self.curriculum, "terrain_levels", None) is not None:
            if self.scene.terrain.terrain_generator is not None:
                self.scene.terrain.terrain_generator.curriculum = True
        else:
            if self.scene.terrain.terrain_generator is not None:
                self.scene.terrain.terrain_generator.curriculum = False
```

### 参数速查表

#### 第一优先：整体效果

| 图名                          | 健康信号                                    |
| --------------------------- | --------------------------------------- |
| `Train/mean_reward`         | **主图**，应上升并收敛到高位                        |
| `Train/mean_episode_length` | 应逐渐接近 **400**（20s × 50Hz = 400 步，即从不早退） |

#### 第二优先：任务分解诊断

| 图名                                    | 健康信号                  |
| ------------------------------------- | --------------------- |
| `Episode_Reward/track_lin_vel_xy_exp` | 上升 → 平移速度跟踪变好         |
| `Episode_Reward/track_ang_vel_z_exp`  | 上升 → 转向跟踪变好           |
| `Metrics/base_velocity/error_vel_xy`  | **下降** → 速度误差直接指标     |
| `Metrics/base_velocity/error_vel_yaw` | **下降** → 转向误差         |
| `Episode_Termination/base_contact`    | 下降 → 摔倒越来越少           |
| `Episode_Termination/bad_orientation` | 下降 → 翻车越来越少           |
| `Episode_Termination/time_out`        | **上升** → 越来越多回合跑满 20s |

#### 第三优先：训练稳定性

| 图名                                     | 健康信号          |
| -------------------------------------- | ------------- |
| `Loss/value_function`、`Loss/surrogate` | 不爆炸，趋势平缓下降    |
| `Policy/mean_noise_std`                | 逐渐减小（探索 → 利用） |
| `Perf/*`                               | 性能监控，不用管      |

#### 最快的看法

TensorBoard 右侧把 **Smoothing 调到 0.9** 左右，然后重点盯这三张：

1. **`Train/mean_reward`** —— 一路上升就说明在学
2. **`Train/mean_episode_length`** —— 冲到 400 附近且稳住 = 基本不摔了
3. **`Metrics/base_velocity/error_vel_xy`** —— 越低走路跟命令越准

另外注意到你训练了 **2000 个 iteration**，模型存到 `model_1999.pt`。如果 `mean_reward` 还在明显上升没收敛，可以加载这个模型继续训练（`--resume` 或把 checkpoint 路径传给 runner），不一定要从头再来。

### 自定义RewardManager

继承并重写RewardManager，它是 IsaacLab 众多 Manager 之一，是 `RewardsCfg` 这张“配置单”的**执行者**。你在 Cfg 里写的是静态声明，真正在训练循环里每一步跑起来的是 RewardManager。

![](D:\Users\XueLi_G\Desktop\C_work\学习笔记\isaac-learning\images\02.png)

在 `source\Xgo_demo\Xgo_demo\tasks\manager_based\xgo_demo` 路径下创建`aer_env.py`文件

```python
from __future__ import annotations

import torch

from isaaclab.envs import ManagerBasedRLEnv
from isaaclab.managers import CommandManager, CurriculumManager, RewardManager, TerminationManager

class AERRewardManager(RewardManager):
    positive_terms = {"energy_new_actual", "track_lin_vel_xy", "track_ang_vel_z"}
    sigma_aux = 0.2

    def compute(self, dt: float) -> torch.Tensor:
        self._reward_buf[:] = 0.0
        positive_reward = torch.zeros_like(self._reward_buf)
        negative_reward = torch.zeros_like(self._reward_buf)
        for term_idx, (name, term_cfg) in enumerate(zip(self._term_names, self._term_cfgs)):
            if term_cfg.weight == 0.0:
                self._step_rewards[:, term_idx] = 0.0
                continue

            value = term_cfg.func(self._env, **term_cfg.params) * term_cfg.weight
            self._step_reward[:, term_idx] = value

            if name in self.positive_terms:
                positive_reward += value
            else:
                negative_reward += value

        self._reward_buf[:] = positive_reward * torch.exp(negative_reward / self.sigma_aux) * dt
        return self._reward_buf

class AERManagerBasedRLEnv(ManagerBasedRLEnv):
    def load_managers(self):
        # note: this order is important since observation manager needs to know the command and action managers
        # and the reward manager needs to know the termination manager
        # -- command manager
        self.command_manager: CommandManager = CommandManager(self.cfg.commands, self)
        print("[INFO] Command Manager: ", self.command_manager)

        # call the parent class to load the managers for observations and actions.
        super().load_managers()

        # prepare the managers
        # -- termination manager
        self.termination_manager = TerminationManager(self.cfg.terminations, self)
        print("[INFO] Termination Manager: ", self.termination_manager)
        # -- reward manager
        self.reward_manager = AERRewardManager(self.cfg.rewards, self)
        print("[INFO] Reward Manager: ", self.reward_manager)
        # -- curriculum manager
        self.curriculum_manager = CurriculumManager(self.cfg.curriculum, self)
        print("[INFO] Curriculum Manager: ", self.curriculum_manager)

        # setup the action and observation spaces for Gym
        self._configure_gym_env_spaces()

        # perform events at the start of the simulation
        if "startup" in self.event_manager.available_modes:
            self.event_manager.apply(mode="startup")
```

# 附录：算力自由平台镜像BUG

### torch 的 CUDA 数学库加载失败（核心问题）

```
RuntimeError: Error in dlopen: libtorch_cuda_linalg.so: cannot open shared object file
```

**为什么文件存在却加载不到？**

- PyTorch 对它的 CUDA 数学库（`libtorch_cuda_linalg.so` 等）是**懒加载**的——用**裸文件名** `dlopen("libtorch_cuda_linalg.so")` 去加载，而不是完整路径。
- 你用 `ldd 完整路径` 能查到依赖，因为给的是全路径；但 `dlopen` 裸名只会搜索 `LD_LIBRARY_PATH`、调用方的 rpath、系统默认路径。
- 而你的 `LD_LIBRARY_PATH` 里只有 `/opt/vulkan/...`、系统库、`/usr/local/cuda/lib64`，**唯独没有 torch 自己的 `torch/lib` 目录**——torch 的库装在 `site-packages/torch/lib`，这个非标准位置不在动态链接器的默认搜索路径里。
- 于是文件在那儿，加载器却"按名字找不到"。

**本质原因**：pip 装的 torch 把 `.so` 放在了系统默认搜索不到的位置，而 torch 懒加载 CUDA 库时又不带路径，只报裸名，两者叠加就触发了这个假"缺失"。

---

## 永久生效方案

验证修复时用的是临时的 `export`，只在当前 shell 有效。选下面**方案 B**（最彻底，可免疫 Isaac Sim 启动时改写 `LD_LIBRARY_PATH`）：

### 方案 B：写入系统 ld 配置（推荐）

```bash
echo "/opt/conda/envs/isaaclab/lib/python3.11/site-packages/torch/lib" > /etc/ld.so.conf.d/torch.conf
ldconfig
```

**为什么选它**：Isaac Sim 的 `AppLauncher` 启动时会重写 `LD_LIBRARY_PATH`，如果只用 bashrc 里的 `export`，有被覆盖的风险。写进 `/etc/ld.so.conf.d` + `ldconfig` 后，这个目录进入**系统全局**的共享库缓存，无论 `LD_LIBRARY_PATH` 怎么变都能找到，一次搞定、永久生效。

### 方案 A（可选，配合）写进 bashrc

```bash
echo 'export LD_LIBRARY_PATH=/opt/conda/envs/isaaclab/lib/python3.11/site-packages/torch/lib:$LD_LIBRARY_PATH' >> ~/.bashrc
source ~/.bashrc
```

建议两个都做：**方案 B 保证系统层面一定能找到**，**方案 A 作为当前 shell 和常规会话的兜底**。
