## 0. 一个理解框架：配置表 + 执行器

`ManagerBasedRlEnvCfg` 里塞了 8 张「配置表」（字典），运行时由各自的 Manager 读表并调用「执行器」：

| 模块 | 配置字典 | 运行时解释 |
|---|---|---|
| 观测 | `observations` | ObservationManager |
| 动作 | `actions` | ActionManager |
| 命令 | `commands` | CommandManager |
| 事件 | `events` | EventManager |
| 奖励 | `rewards` | RewardManager |
| 终止 | `terminations` | TerminationManager |
| 课程 | `curriculum` | CurriculumManager |
| 度量 | `metrics` | MetricsManager |

每个配置 = `XxxTermCfg(func=函数, weight/params=...)`。`func` 要么是 mjlab 内置函数，要么是 luwu_mjlab 在 `src/tasks/velocity/mdp/` 下的自定义。`src/tasks/velocity/mdp/__init__.py` 先 `from mjlab.envs.mdp import *` 再导入本地覆盖，所以 `mdp.xxx` 是「内置 + 本地」的混合。**看清函数从哪来，是读懂这套代码的关键。**

## 1. 观测模块 `observations`

分两组：`actor`（策略输入）和 `critic`（价值网络输入，通常比 actor 多特权信息）。`concatenate_terms=True` 表示把各 term 拼成一个向量；`enable_corruption` 是训练时给 actor 观测加扰动的开关，每一项的 `noise` 是扰动范围（域随机化，第 3 篇细讲）。

| term | 函数 | 含义 / 原理 |
|---|---|---|
| base_ang_vel | imu_ang_vel | 机身角速度（IMU），判断姿态变化速率 |
| projected_gravity | projected_gravity | 重力方向投影到机身系，编码「倾斜程度」 |
| command | generated_commands | 当前期望速度指令（让策略知道目标） |
| phase | phase | 步态相位 sin/cos，帮助生成周期步态 |
| joint_pos / joint_vel | joint_pos_rel / joint_vel_rel | 关节位置/速度（相对默认位型） |
| actions | last_action | 上一拍实际动作（利于学出平滑策略） |
| height_scan | height_scan | 地形高度扫描（仅崎岖地形用，平地删掉） |
| base_lin_vel（仅 critic） | imu_lin_vel | 机身线速度——真机没有，属「特权观测」 |
| foot_height / air_time / contact / forces（仅 critic） | 见 `mdp/observations.py` | 足端高度/腾空时间/接触/接触力 |

**原理要点**：actor 只放真机上能量到的量（IMU、关节角、命令、相位），critic 多放 `base_lin_vel` 这类特权量——这正是「教师-学生」范式（真机部署只让学生依赖 actor 观测）的前提，与 isaac 笔记第 3 篇遥相呼应。

## 2. 动作模块 `actions`

```python
actions = {
  "joint_pos": JointPositionActionCfg(
    entity_name="robot",
    actuator_names=(".*",),     # 控制所有位置伺服
    scale=0.25,                 # 策略输出 ∈[-1,1] → 实际偏移 ±0.25 rad
    use_default_offset=True,    # 以默认位型为基准做偏移
  )
}
```

**原理**：四足常用「位置环」控制——策略输出的是相对默认位型的关节角度增量。`scale=0.25` 限制单步动作幅度：太小站不起来，太大容易发散。工厂默认就是 0.25，Lite3 显式保持 0.25。`HeldJointPositionAction`（`mdp/actions.py`）是 walk 用不到的变体，用于翻身任务先「保持默认位型 2 秒再动」。

## 3. 命令模块 `commands`

```python
commands = {
  "twist": UniformVelocityCommandCfg(
    entity_name="robot",
    resampling_time_range=(3.0, 8.0),   # 每 3~8 秒重采样一次指令
    rel_standing_envs=0.05,             # 5% 环境指令=0（练静止）
    heading_command=True,               # 用朝向跟踪替代直接角速度
    ranges=UniformVelocityCommandCfg.Ranges(
      lin_vel_x=(-1.0, 2.0),
      lin_vel_y=(-1.0, 1.0),
      ang_vel_z=(-1.0, 1.0),
      heading=(-math.pi, math.pi),
    ),
  )
}
```

**原理**：任务的「目标」机制。twist = 期望线速度(vx,vy) + 角速度(wz)。`UniformVelocityCommand`（`mdp/velocity_command.py`）隔一段时间随机采样一个指令；`heading_command=True` 时用 `heading_control_stiffness * 朝向误差` 换算成角速度指令。平地走路任务（Lite3-Walk）会 `heading_command=False` 并把范围收窄（如 `lin_vel_x=(-0.2,0.4)`）。

## 4. 奖励模块 `rewards`（核心，对应 isaac 笔记第 2 篇「设计奖励函数」）

`RewardTermCfg(func, weight, params)`：`weight` 可正（奖励）可负（惩罚）。总奖励 = Σ weight_i × term_i。

| 奖励 | 函数 | 公式/原理 | Lite3 覆写 |
|---|---|---|---|
| track_linear_velocity | track_linear_velocity | exp(-‖v_cmd − v_actual‖²/std²)，速度跟踪主奖励 | weight 1→4.0，std→0.15 |
| track_angular_velocity | track_angular_velocity | 同样高斯形式，角速度/朝向跟踪 | weight→4.0 |
| body_orientation_l2 | body_orientation_l2 | 惩罚投影重力 xy 分量（越大越歪） | weight −1→−2.0 |
| pose | variable_posture | exp(-mean(e²/std²))，按速度分 standing/walking/running 三档 std 的默认位型正则 | 每关节 std 单独配 |
| body_ang_vel | body_angular_velocity_penalty | 惩罚机身 xy 角速度过大 | −0.05→−0.08 |
| angular_momentum | angular_momentum_penalty | 惩罚全身角动量，抑制甩臂 | −0.025→−0.03 |
| is_terminated | is_terminated | 终止时给 −200，教它别停 | 不变 |
| joint_acc_l2 / joint_pos_limits / action_rate_l2 | … | 关节加速度/限位/动作平滑惩罚 | action_rate 调 −0.2 |
| foot_gait | feet_gait | 步态相位是否与预期支撑态一致（对角线步态） | period→0.4，offset=[0,0.5,0,0.5] |
| foot_clearance | feet_clearance | 惩罚离地高度偏离 target_height，按足速加权 | target→0.02 |
| foot_slip | feet_slip | 惩罚触地时足端水平滑动 | −0.25→−0.05 |
| soft_landing | soft_landing | 惩罚落地冲击力 | 不变 |
| stand_still | stand_still | 静止指令时要求保持默认位型 | 不变 |
| nonfoot_contact | illegal_contact | 除足端外身体其他部位触地 → 罚 | Lite3 新增 −3 |

**原理要点（与 isaac 第 2 篇对应）**：

- 自定义奖励函数：`src/tasks/velocity/mdp/rewards.py` 就是「自定义奖励函数」的落点，例如 `track_linear_velocity` 就是手写的（见 `mdp/rewards.py` 的 `track_linear_velocity` 函数）。
- 自定义 RewardManager：mjlab 里等价玩法是写**有状态的奖励类**，如 `variable_posture`、`feet_swing_height`（带 `__init__` + `__call__`，维护跨 step 的状态如峰值高度）。
- 权重是「竞赛」：跟踪奖励给大正权重（4.0），姿态/平滑给负权重——正的大项推着学走路，负的小项只是约束。

**Lite3 的奖励覆写长这样**（`lite3_walk/env_cfgs.py` 节选，配合上表看）：

```python
cfg.rewards["track_linear_velocity"].weight = 4.0
cfg.rewards["track_linear_velocity"].params["std"] = 0.15
cfg.rewards["body_ang_vel"].weight = -0.08
cfg.rewards["foot_gait"].weight = 1.0
cfg.rewards["foot_gait"].params["offset"] = [0.0, 0.5, 0.0, 0.5]
cfg.rewards["pose"].params["std_standing"] = {
  r".*(FL|FR|RL|RR)_hip_joint.*": 0.05,
  r".*(FL|FR|RL|RR)_thigh_joint.*": 0.1,
  r".*(FL|FR|RL|RR)_shank_joint.*": 0.15,
  r"^mainarm_joint$": 0.1,
  r"^forearm_joint$": 0.1,
}
```

## 5. 终止模块 `terminations`

```python
terminations = {
  "time_out": TerminationTermCfg(func=mdp.time_out, time_out=True),
  "fell_over": TerminationTermCfg(
    func=mdp.bad_orientation, params={"limit_angle": math.radians(70.0)}
  ),
}
```

**原理**：满足条件即提前结束本 episode 并触发 reset。`time_out` 是 20s 时间上限；`fell_over` 是机身倾斜超 70° 判倒。Lite3 还加 `illegal_contact`（非足端触地达 10 N 即终止）——「摔了/磕了就别再练」的硬约束。

## 6. 事件模块 `events`（本篇先看结构，随机化留到第 3 篇）

```python
events = {
  "reset_base":       EventTermCfg(func=mdp.reset_root_state_uniform, mode="reset", ...),
  "reset_robot_joints": EventTermCfg(func=mdp.reset_joints_by_offset, mode="reset", ...),
  "push_robot":       EventTermCfg(func=mdp.push_by_setting_velocity, mode="interval", ...),
  "foot_friction":    EventTermCfg(mode="startup", func=dr.geom_friction, ...),
  "encoder_bias":     EventTermCfg(mode="startup", func=dr.encoder_bias, ...),
  "base_com":         EventTermCfg(mode="startup", func=dr.body_com_offset, ...),
}
```

`mode` 三种：`reset`（episode 开始）、`interval`（周期性）、`startup`（启动一次）。后三个 `dr.*` 是域随机化，第 3 篇细讲。

## 7. 课程模块 `curriculum`

```python
curriculum = {
  "terrain_levels": CurriculumTermCfg(func=mdp.terrain_levels_vel, ...),
  "command_vel": CurriculumTermCfg(
    func=mdp.commands_vel,
    params={"command_name": "twist", "velocity_stages": [
      {"step": 0, "lin_vel_x": (-0.5, 1.0), ...},           # 先慢
      {"step": 5000 * 24, "lin_vel_x": (-1.0, 2.0), ...},   # 到此步再放开速度
    ]},
  ),
}
```

**原理（对应 isaac 第 2 篇「配置 Commands 和 Curriculum」）**：`commands_vel` 按全局训练步数分段放开指令范围，从慢到快；`terrain_levels_vel` 按「走了多远」升降地形难度。平地任务两个都 `pop` 掉（见 `lite3_walk/env_cfgs.py` 里的 `cfg.curriculum.pop("command_vel", None)`）。

## 8. 关键调参（对照 isaac 第 2 篇「参数优化」）

| 参数 | 位置 | 建议 |
|---|---|---|
| `num_envs` | `--env.scene.num-envs` | 显存够就 4096，小就 256~1024 |
| `max_iterations` | `--agent.max-iterations` | 先 20 验证，再 1500 练效果 |
| 奖励权重 | `cfg.rewards[*].weight` | 看 TensorBoard 单项 reward，跟踪项是否达标 |
| 动作 scale | `cfg.actions["joint_pos"].scale` | 抬腿吃力→加大；抖/发散→减小 |
| timestep / decimation | `cfg.sim.mujoco.timestep` / `cfg.decimation` | Lite3 用 0.004 s + decimation 5 → 控制频率 50 Hz |
| PPO init_std/gamma/entropy | rl_cfg | 探索不足→init_std 或 entropy ↑ |

**最快的读法（和 isaac 第 1 篇「参数速查表」一致）**：先看整体 `mean reward` 是否上升且不崩；再看 `track_*_velocity` 是否逼近 1（=完全跟踪）；最后看 `fell_over`/`illegal_contact` 是否频繁触发。
