# 按官方教程从零创建新任务

> 对应 isaac-learning 笔记第 1 篇「isaac-lab 搭建强化学习框架」。isaac 那边用 `./isaaclab.sh --new` 一键生成模板项目；**mjlab 没有这种命令行生成器**（1.2.0 的命令只有 `train / play / list_envs / demo / export-scene / viz-nan`，本地已验证），官方的「创建新任务」教程是仓库里的笔记本 [create_new_task.ipynb](https://github.com/mujocolab/mjlab/blob/main/notebooks/create_new_task.ipynb)（可在 Colab 直接跑）：从零手写一个 **CartPole** 倒立摆任务，四步走——**定义机器人 → 定义任务 MDP → 注册 → 训练**。本篇把这本官方笔记本搬到 Windows 本机逐步执行，并讲清每步背后的机制。

## 0. 核心思路：新任务「长在」mjlab 源码树里

官方 `train / play` 启动时只做一件事：`import mjlab.tasks`。而 `mjlab/tasks/__init__.py` 的全部内容是：

```python
from mjlab.utils.lab_api.tasks.importer import import_packages

_BLACKLIST_PKGS = ["utils", ".mdp"]

import_packages(__name__, _BLACKLIST_PKGS)
```

`import_packages` 会**递归 import** `mjlab/tasks/` 下所有子包——所以只要在 `mjlab/tasks/` 下建一个新目录、放一个带 `register_mjlab_task(...)` 的 `__init__.py`，官方的 `train / play / list_envs` **立刻就能看到它**，不需要任何额外配置。

代价：新任务必须放进 mjlab 源码树。所以本篇用**源码 + editable 安装**（`pip install -e .`，对源码的修改即时生效，不用反复重装）。

## 1. 第 0 步：获取源码并 editable 安装

```powershell

git clone https://github.com/mujocolab/mjlab.git

# ② 切到与本系列一致的版本（参考项目 luwu_mjlab 基于 1.2.0）

git checkout v1.2.0

# ③ 新建一个 conda 环境（别复用 luwu_mjlab 那个，避免动坏它锁定的依赖）
conda create -n mjlab_dev python=3.11 -y
conda activate mjlab_dev

# ④ editable 安装：之后对 src/mjlab/ 的任何修改立即生效

```

验证（此时跑的已经是你的本地源码）：

```powershell

```

能列出 `Mjlab-Velocity-Flat-Unitree-Go1` 等官方任务即成功。**之后所有命令都在仓库根目录执行**（日志会写到当前目录的 `logs/`）。

## 2. 第 1 步：定义机器人（进 asset_zoo）

CartPole = 1 个滑轨小车 + 1 根铰接杆，2 个自由度。官方笔记本把它作为新机器人加进 `asset_zoo`（mjlab 的机器人库）。目录结构：

```
src/mjlab/asset_zoo/robots/cartpole/
├── __init__.py            # 空文件，标记这是 Python 包
├── cartpole_constants.py  # 机器人配置
└── xmls/
    └── cartpole.xml       # 物理模型
```

### 2.1 MuJoCo XML：`xmls/cartpole.xml`

```xml
<mujoco model="cartpole">
  <compiler angle="degree" coordinate="local" inertiafromgeom="true"/>
  <worldbody>
    <geom name="ground" type="plane" pos="0 0 0" size="5 5 0.1" rgba="0.8 0.9 0.8 1"/>
    <body name="cart" pos="0 0 0.1">
      <geom type="box" size="0.2 0.1 0.1" rgba="0.2 0.2 0.8 1" mass="1.0"/>
      <joint name="slide" type="slide" axis="1 0 0" limited="true" range="-2 2"/>
      <body name="pole" pos="0 0 0.1">
        <geom type="capsule" size="0.05 0.5" fromto="0 0 0 0 0 1" rgba="0.8 0.2 0.2 1" mass="2.0"/>
        <joint name="hinge" type="hinge" axis="0 1 0" range="-90 90"/>
      </body>
    </body>
  </worldbody>
  <actuator>
    <velocity name="slide_velocity" joint="slide" ctrlrange="-20 20" kv="20"/>
  </actuator>
</mujoco>
```

**要点**：`qpos[0]` = 小车位置（slide 关节），`qpos[1]` = 杆角度（hinge 关节）；执行器是 `<velocity>` 型——控制指令是**期望速度**，MuJoCo 内置的 `kv` 增益负责追踪。这就是 CartPole 的全部物理。

### 2.2 机器人配置：`cartpole_constants.py`

```python
from pathlib import Path
import mujoco

from mjlab import MJLAB_SRC_PATH
from mjlab.entity import EntityCfg, EntityArticulationInfoCfg
from mjlab.actuator import XmlVelocityActuatorCfg

CARTPOLE_XML: Path = (
  MJLAB_SRC_PATH / "asset_zoo" / "robots" / "cartpole" / "xmls" / "cartpole.xml"
)
assert CARTPOLE_XML.exists(), f"XML not found: {CARTPOLE_XML}"


def get_spec() -> mujoco.MjSpec:
  return mujoco.MjSpec.from_file(str(CARTPOLE_XML))


def get_cartpole_robot_cfg() -> EntityCfg:
  """Get a fresh CartPole robot configuration instance."""
  actuators = (
    XmlVelocityActuatorCfg(target_names_expr=("slide",)),
  )
  articulation = EntityArticulationInfoCfg(actuators=actuators)
  return EntityCfg(spec_fn=get_spec, articulation=articulation)
```

**逐行拆**：

- `EntityCfg` 是 mjlab 里「一个机器人」的统一封装：`spec_fn` 给出 MuJoCo 模型（惰性加载，每次调用返回全新 `MjSpec`，避免多环境共享状态），`articulation` 描述执行器。
- `XmlVelocityActuatorCfg(target_names_expr=("slide",))`：把 XML 里挂在 `slide` 关节上的 `<velocity>` 执行器包给 mjlab 管。
- ⚠️ **版本差异（本地已核对）**：官方笔记本（main 分支）这里用的是统一的 `XmlActuatorCfg`；**1.2.0 里没有这个类**，只有分类型的 `XmlVelocityActuatorCfg` / `XmlPositionActuatorCfg` 等。克隆 main 跑笔记本按笔记本写，用 1.2.0 按本文写。

## 3. 第 2 步：定义任务 MDP（`tasks/cartpole/env_cfg.py`）

在 `src/mjlab/tasks/` 下建 `cartpole/` 目录，核心文件 `env_cfg.py`——这就是 isaac 笔记里「环境配置」的 mjlab 版，**六大件**齐了：场景、动作、观测、奖励、事件、终止（以下为官方笔记本原文）：

```python
"""CartPole task environment configuration."""

import math
import torch

from mjlab.envs import ManagerBasedRlEnvCfg
from mjlab.envs.mdp.actions import JointVelocityActionCfg
from mjlab.managers.observation_manager import ObservationGroupCfg, ObservationTermCfg
from mjlab.managers.reward_manager import RewardTermCfg
from mjlab.managers.termination_manager import TerminationTermCfg
from mjlab.managers.event_manager import EventTermCfg
from mjlab.managers.scene_entity_config import SceneEntityCfg
from mjlab.scene import SceneCfg
from mjlab.sim import MujocoCfg, SimulationCfg
from mjlab.viewer import ViewerConfig
from mjlab.asset_zoo.robots.cartpole.cartpole_constants import get_cartpole_robot_cfg
from mjlab.envs import mdp


def cartpole_env_cfg(play: bool = False) -> ManagerBasedRlEnvCfg:
  """Create CartPole environment configuration.

  Args:
    play: If True, disables corruption and extends episode length for evaluation.
  """

  # === Scene ===
  scene_cfg = SceneCfg(
    num_envs=64 if not play else 16,
    extent=1.0,
    entities={"robot": get_cartpole_robot_cfg()},
  )

  viewer_cfg = ViewerConfig(
    origin_type=ViewerConfig.OriginType.ASSET_BODY,
    entity_name="robot",
    body_name="pole",
    distance=3.0,
    elevation=10.0,
    azimuth=90.0,
  )

  sim_cfg = SimulationCfg(
    mujoco=MujocoCfg(
      timestep=0.02,  # 50 Hz 控制
      iterations=1,
    ),
  )

  # === Actions：策略输出 × 20 = 小车期望速度 ===
  actions = {
    "joint_vel": JointVelocityActionCfg(
      entity_name="robot",
      actuator_names=(".*",),
      scale=20.0,
      use_default_offset=False,
    ),
  }

  # === Observations：直接读原生 MuJoCo 数据并做归一化 ===
  actor_terms = {
    "angle": ObservationTermCfg(
      func=lambda env: env.sim.data.qpos[:, 1:2] / math.pi
    ),
    "ang_vel": ObservationTermCfg(
      func=lambda env: env.sim.data.qvel[:, 1:2] / 5.0
    ),
    "cart_pos": ObservationTermCfg(
      func=lambda env: env.sim.data.qpos[:, 0:1] / 2.0
    ),
    "cart_vel": ObservationTermCfg(
      func=lambda env: env.sim.data.qvel[:, 0:1] / 20.0
    ),
  }

  observations = {
    "actor": ObservationGroupCfg(
      terms=actor_terms,
      concatenate_terms=True,
      enable_corruption=not play,  # 训练时加观测噪声，评估关掉
    ),
    "critic": ObservationGroupCfg(
      terms=actor_terms,
      concatenate_terms=True,
      enable_corruption=False,
    ),
  }

  # === Rewards：立杆主奖励 + 控制代价 ===
  def compute_upright_reward(env):
    """Reward for keeping pole upright (cosine of angle)."""
    return env.sim.data.qpos[:, 1].cos()

  def compute_effort_penalty(env):
    """Penalty for control effort."""
    return -0.01 * (env.sim.data.ctrl[:, 0] ** 2)

  rewards = {
    "upright": RewardTermCfg(func=compute_upright_reward, weight=5.0),
    "effort": RewardTermCfg(func=compute_effort_penalty, weight=1.0),
  }

  # === Events：reset 随机初始状态 + 训练时随机推小车 ===
  def random_push_cart(env, env_ids, force_range=(-5, 5)):
    """apply random force to cart for robustness training."""
    n = len(env_ids)
    random_forces = (
      torch.rand(n, device=env.device)
      * (force_range[1] - force_range[0])
      + force_range[0]
    )
    env.sim.data.qfrc_applied[env_ids, 0] = random_forces

  events = {
    "reset_robot_joints": EventTermCfg(
      func=mdp.reset_joints_by_offset,
      mode="reset",
      params={
        "asset_cfg": SceneEntityCfg("robot"),
        "position_range": (-0.1, 0.1),
        "velocity_range": (-0.1, 0.1),
      },
    ),
  }
  if not play:
    events["random_push"] = EventTermCfg(
      func=random_push_cart,
      mode="interval",
      interval_range_s=(1.0, 2.0),
      params={"force_range": (-20.0, 20.0)},
    )

  # === Terminations：杆倾过 30° 或超时 ===
  def check_pole_tipped(env):
    """Check if pole has tipped beyond 30 degrees."""
    return env.sim.data.qpos[:, 1].abs() > math.radians(30)

  terminations = {
    "timeout": TerminationTermCfg(func=mdp.time_out, time_out=True),
    "tipped": TerminationTermCfg(func=check_pole_tipped, time_out=False),
  }

  # === 汇总 ===
  return ManagerBasedRlEnvCfg(
    scene=scene_cfg,
    observations=observations,
    actions=actions,
    rewards=rewards,
    events=events,
    terminations=terminations,
    sim=sim_cfg,
    viewer=viewer_cfg,
    decimation=1,  # 无动作保持
    episode_length_s=int(1e9) if play else 10.0,
  )
```

**六大件逐个说**（算法细节第 2 篇展开，这里先建立骨架认知）：

| 块 | 干什么 | 原理一句话 |
|---|---|---|
| `scene` | 64 个并行环境 + 装入机器人 | GPU 并行是 mjlab（MuJoCo Warp）的核心卖点 |
| `actions` | 策略输出 ∈ [-1,1]，×20 映射为小车期望速度 | `scale` 决定动作幅度，和四足的位置环动作是同一机制 |
| `observations` | 4 个 term：杆角/角速度/车位置/车速度，各自归一化 | **直接读 `env.sim.data.qpos/qvel`**——mjlab 保留原生 MuJoCo 数据结构，观测函数就是普通函数（这里连 lambda 都行） |
| `rewards` | `upright`（cos θ，权重 5）+ `effort`（控制代价） | 主奖励推着学「立杆」，小惩罚约束「别猛打」 |
| `events` | reset 时随机初始状态；训练时每 1~2s 随机推一下小车 | 这是域随机化的雏形（第 3 篇展开） |
| `terminations` | 杆倾过 30° 判负；10s 超时 | 定义 episode 边界 |
| `play` 参数 | 评估模式：16 个环境、关观测噪声、episode 无限长 | 一份配置，训练/部署两用 |

注意 `critic` 组目前和 `actor` 完全一样（CartPole 没有特权信息）；四足任务里 critic 会多出真机上拿不到的量（如机身线速度），这就是「教师-学生」的伏笔。

## 4. 第 3 步：PPO 训练配置 `rl_cfg.py`

```python
"""RL configuration for CartPole task."""

from mjlab.rl.config import (
  RslRlOnPolicyRunnerCfg,
  RslRlModelCfg,
  RslRlPpoAlgorithmCfg,
)


def cartpole_ppo_runner_cfg() -> RslRlOnPolicyRunnerCfg:
  """Create RL runner configuration for CartPole task."""
  return RslRlOnPolicyRunnerCfg(
    actor=RslRlModelCfg(
      hidden_dims=(256, 128, 64),  # 任务简单，用小网络
      activation="elu",
      obs_normalization=True,
      distribution_cfg={
        "class_name": "GaussianDistribution",
        "init_std": 1.0,
        "std_type": "scalar",
      },
    ),
    critic=RslRlModelCfg(
      hidden_dims=(256, 128, 64),
      activation="elu",
      obs_normalization=True,
    ),
    algorithm=RslRlPpoAlgorithmCfg(
      value_loss_coef=1.0,
      use_clipped_value_loss=True,
      clip_param=0.2,
      entropy_coef=0.01,
      num_learning_epochs=5,
      num_mini_batches=4,
      learning_rate=1.0e-3,
      schedule="adaptive",   # 按 KL 自动调学习率
      gamma=0.99,
      lam=0.95,
      desired_kl=0.01,
      max_grad_norm=1.0,
    ),
    experiment_name="cartpole",
    save_interval=50,
    num_steps_per_env=24,
    max_iterations=5_000,
  )
```

三个要点：**小网络**（256-128-64，任务简单）、**obs_normalization=True**（观测归一化，四足官方模板反而是关的）、**adaptive 学习率**（以 desired_kl 为目标自动升降）。

## 5. 第 4 步：注册任务 `tasks/cartpole/__init__.py`

```python
"""CartPole task registration."""

from mjlab.tasks.registry import register_mjlab_task
from mjlab.rl.runner import MjlabOnPolicyRunner

from .env_cfg import cartpole_env_cfg
from .rl_cfg import cartpole_ppo_runner_cfg

register_mjlab_task(
  task_id="Mjlab-Cartpole",
  env_cfg=cartpole_env_cfg(),
  play_env_cfg=cartpole_env_cfg(play=True),
  rl_cfg=cartpole_ppo_runner_cfg(),
  runner_cls=MjlabOnPolicyRunner,
)
```

`register_mjlab_task` 四要素：**task_id**（命令行里用它选任务）、**env_cfg**（训练配置）、**play_env_cfg**（评估/回放配置，即 `play=True` 那份）、**rl_cfg**（PPO 配置）。`runner_cls` 用通用的 `MjlabOnPolicyRunner` 即可（luwu 用的 `VelocityOnPolicyRunner` 是为了多一个 ONNX 导出，第 3 篇讲）。

验证注册：

```powershell
python -m mjlab.scripts.list_envs
```

列表里出现 `Mjlab-Cartpole` —— 官方命令已经能看到你的任务了。

## 7. 机制回顾 + 从 CartPole 到四足

### 7.1 为什么什么额外配置都没做就生效了

回顾一遍链条：editable 安装 → `src/mjlab/tasks/cartpole/__init__.py` 成为 `mjlab.tasks.cartpole` 包的一部分 → 官方脚本 `import mjlab.tasks` 时 `import_packages` 递归 import 到它 → `register_mjlab_task` 把任务写进全局注册表 → `list_tasks()` 能列出 → tyro 命令行能选。**整个「注册」动作就是 import 副作用**。

### 7.2 四足模板 = 同一模式的官方完整版

官方 `tasks/velocity/config/go1/` 三件套（`env_cfgs.py / rl_cfg.py / __init__.py`）就是「CartPole 三件套」的 locomotion 完整版——结构一模一样，只是 MDP 复杂得多。复制它就得到自己的四足任务模板：

```powershell
# 在仓库根目录
Copy-Item -Recurse src\mjlab\tasks\velocity\config\go1 src\mjlab\tasks\velocity\config\go1_demo
```

两处最小修改：

1. `go1_demo/__init__.py`：把注册改成只保留 flat 一个，`task_id="My-Velocity-Flat-Unitree-Go1"`（原 ID 已被官方 go1 注册过，不改会报 `already registered`）；
2. `go1_demo/rl_cfg.py`：`experiment_name="go1_demo"`（隔离日志目录）。

验证（零动作冒烟测试，不需要任何模型）：

```powershell
python -m mjlab.scripts.play My-Velocity-Flat-Unitree-Go1 --agent zero
```

viewer 里 Go1 站在平地上不报错，模板就绪。换 Lite3 机器人、填奖励/观测算法，是第 2 篇的事。

### 7.3 对照：luwu_mjlab 的另一种扩展姿势

| | 本篇（官方笔记本路线） | luwu_mjlab 路线 |
|---|---|---|
| 任务放哪 | mjlab 源码树 `mjlab/tasks/` 里 | 独立项目 `src/tasks/` 里 |
| 谁来发现 | 官方 `train/play`（`import mjlab.tasks`） | 自带的 `scripts/train.py`（多一句 `import src.tasks`） |
| 优点 | 零配置、和官方任务平起平坐 | 不动框架源码，可独立发布/版本管理 |
| 代价 | 改的是框架源码，升级要合并 | 每个入口脚本要自己维护一份 |

两者机制完全同源（都是「import 到 → 注册」）。luwu 选独立项目是因为它要对外发布、且锁死 mjlab==1.2.0；**学习/实验阶段用本篇的源码树路线最省事**。第 2 篇拆解的 `make_velocity_env_cfg()` 工厂在两边是同一套（luwu 复刻并定制了一份），讲法通用。

## 8. 进阶实操：按 luwu 的方式构建独立扩展项目

§7.3 说过另一条路：不碰框架源码，把任务放在**自己的独立项目**里（luwu_mjlab 就是这么做的）。这一节从零把骨架搭出来——完成后你会得到一个和 luwu 同构、可以独立发布的项目，而且**不需要 editable 安装**，用 pip 装的 mjlab 就行。

### 8.1 目标结构

```
my_quadruped/                  # 项目根目录（名字随意，git init 一下就是你的仓库）
├── my_tasks/                  # 自己的任务包（对应 luwu 的 src/tasks/）
│   ├── __init__.py            # 自动发现入口（见 8.2）
│   └── velocity/
│       ├── __init__.py        # 空
│       └── config/
│           ├── __init__.py    # 空
│           └── go1_demo/      # 复制官方 go1 三件套（见 8.3）
│               ├── __init__.py
│               ├── env_cfgs.py
│               └── rl_cfg.py
├── train.py                   # 三个入口脚本（见 8.4）
├── play.py
└── list_envs.py
```

### 8.2 搭骨架

```powershell
mkdir my_quadruped; cd my_quadruped
mkdir my_tasks\velocity\config
"" | Out-File my_tasks\__init__.py -Encoding utf8   # 先建空的，下面重写
"" | Out-File my_tasks\velocity\__init__.py -Encoding utf8
"" | Out-File my_tasks\velocity\config\__init__.py -Encoding utf8
```

把 `my_tasks/__init__.py` 重写为（和 luwu 的 `src/tasks/__init__.py` 同款，就两行核心）：

```python
from mjlab.utils.lab_api.tasks.importer import import_packages

import_packages(__name__)
```

`import_packages` 递归 import `my_tasks/` 下所有子包——所以以后每次往 `config/` 里丢一个新任务目录，都会被自动发现，不用改这里。

### 8.3 复制官方 Go1 模板进来

来源用第 1 节克隆的源码树（或任何装了 mjlab 的环境里 `python -c "import mjlab, os; print(os.path.dirname(mjlab.__file__))"` 给出的路径）：

```powershell
Copy-Item -Recurse <mjlab源码目录>\src\mjlab\tasks\velocity\config\go1 my_tasks\velocity\config\go1_demo
```

最小修改和 §7.2 完全一样（`go1_demo` 在**你的项目**里，改起来放心）：

1. `go1_demo/__init__.py`：只保留 flat 注册，`task_id="My-Velocity-Flat-Unitree-Go1"`；
2. `go1_demo/rl_cfg.py`：`experiment_name="go1_demo"`。

### 8.4 三个入口脚本（与 luwu 的本质差异就在这）

官方 `train/play` 看不见 `my_tasks`，所以自带入口，先 import 自己的任务包、再复用官方流程。以 `train.py` 为例（`play.py` / `list_envs.py` 只需换 import 的模块名）：

```python
"""训练入口：先注册自己的任务，再复用 mjlab 官方训练流程。"""
import my_tasks  # noqa: F401  # 导入即注册

from mjlab.scripts.train import main

if __name__ == "__main__":
  main()
```

```python
# play.py → from mjlab.scripts.play import main
# list_envs.py → from mjlab.scripts.list_envs import main
```

就这 4 行——luwu 把官方脚本整份复制再改（它要改默认环境数、tracking 逻辑），我们只需最小委托，效果一样。

### 8.5 验证

```powershell

python list_envs.py --keyword Go1     # 应同时看到官方的和 My-Velocity-Flat-Unitree-Go1
python play.py My-Velocity-Flat-Unitree-Go1 --agent zero   # 零动作冒烟测试
python train.py My-Velocity-Flat-Unitree-Go1 --env.scene.num-envs 256 --agent.max-iterations 20
```

注意两点：**必须在项目根目录运行**（`import my_tasks` 依赖当前目录进 `sys.path`，日志也写在当前目录的 `logs/`）；以后加自定义奖励/观测函数时，仿照 luwu 建 `my_tasks/velocity/mdp/` 包，并把 8.2 的 `import_packages(__name__)` 改成 luwu 的写法 `import_packages(__name__, ["utils", ".mdp"])`。

### 8.6 什么时候用这条路线

- 任务要**独立版本管理 / 对外发布**（luwu 的场景）；
- 要**锁定 mjlab 版本**（luwu 锁 1.2.0），不想跟着框架 main 走；
- 多个实验项目共享同一份 pip 安装的 mjlab，互不干扰。

学习期可以两条路并用：源码树里快速试想法（§0~§7），成熟后搬进独立项目。luwu 的 `src/tasks/` 结构和 `my_tasks/` 一一对应，第 2 篇讲的所有模块填法在两种路线下通用。

## 9. 小结

- mjlab 官方「创建新任务」教程 = `create_new_task.ipynb`：**机器人 XML → EntityCfg → env_cfg 六大件 → rl_cfg → register_mjlab_task → train**。
- 新任务长在源码树里，靠 `import_packages` 递归 import 被官方命令自动发现；editable 安装让改动即时生效。
- 全流程 4 个文件 + 1 个 XML，没有任何脚手架工具——这就是官方设计哲学：结构极简，一切是普通 Python。
- 四足模板 = 复制官方 go1 三件套 + 改 task_id / experiment_name 两个字符串。
- 不想动框架源码时，用 §8 的独立扩展项目（luwu 同构）：自己的任务包 + `import_packages` 自动发现 + 三个 4 行入口脚本，pip 安装的 mjlab 即可。
