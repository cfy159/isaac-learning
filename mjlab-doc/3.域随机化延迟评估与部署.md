# 域随机化、延迟与评估部署

> 对应 isaac-learning 笔记第 3 篇「教师学生模型蒸馏」的精神：从「能训练」走向「能上真机」。luwu_mjlab 没有单独的蒸馏实现，但提供了上真机的一套关键能力——**延迟模拟 + 域随机化 + ONNX 导出**，本篇讲全，并用 tracking 脚手架讲「如何扩展新任务」。

## 1. 延迟模拟（sim-to-real 的第一要义）

真机从「观测 → 决策 → 下发执行器 → 生效」有一两拍延迟；仿真若不带这段延迟，训出的策略上真机会抖、不稳。luwu_mjlab 在 `src/tasks/velocity/latency.py` 里做了两类延迟，**只在训练时启用，play 回放时关闭**：

| 函数 | 作用 | 默认 lag |
|---|---|---|
| `apply_joint_feedback_delay(cfg)` | 关节位置/速度观测延迟 | 1~2 步 |
| `with_delayed_articulation(robot_cfg)` | 执行器指令延迟 | 1~2 步 |

Lite3 任务这样用（`lite3_walk/env_cfgs.py`）：

```python
from src.tasks.velocity.latency import apply_joint_feedback_delay, with_delayed_articulation
...
cfg.scene.entities = {"robot": with_delayed_articulation(get_lite3_walk_robot_cfg(), play=play)}
...
apply_joint_feedback_delay(cfg, play=play)
```

> 注意 `play=` 参数：play 模式下 `min_lag=max_lag=0`，即回放/上真机评估时不要延迟。

## 2. 域随机化 `events`

`mode="startup"` 的那几个 `dr.*` 事件，作用是在训练时随机化物理参数，逼策略对参数扰动鲁棒：

| 事件 | 函数 | 随机化什么 | 意义 |
|---|---|---|---|
| foot_friction | dr.geom_friction | 足端摩擦系数 0.2~3.0（Lite3 覆写） | 抗不同地面 |
| encoder_bias | dr.encoder_bias | 编码器零偏 ±0.04 | 抗传感器零漂 |
| base_com | dr.body_com_offset | 质心偏移 ±0.035 | 抗质量分布差异/负载 |
| push_robot | mdp.push_by_setting_velocity | 周期随机推一下（interval） | 抗外部扰动 |

`mode="reset"` 的 `reset_base`（随机初始位姿）和 `reset_robot_joints` 也是广义随机化——让策略从各种初始状态学会稳定。

## 3. 训练

```bash
# 单卡
python scripts/train.py Lite3-Walk-Flat --env.scene.num-envs 4096

# 指定/多卡
python scripts/train.py Lite3-Walk-Flat --env.scene.num-envs 4096 --gpu-ids [0,1]

# 更多迭代 + 从检查点恢复
python scripts/train.py Lite3-Walk-Flat --agent.max-iterations 3000 --agent.resume
```

| 参数 | 说明 |
|---|---|
| `--env.scene.num-envs N` | 并行环境数 |
| `--agent.max-iterations N` | 迭代数 |
| `--agent.resume` | 从最新检查点恢复 |
| `--gpu-ids all` / `[0,1]` | GPU 选择 |
| `--video` | 录制训练视频 |
| `--enable-nan-guard` | 开启 NaN 保护 |

日志在 `logs/rsl_rl/<experiment_name>/<时间戳>/`，含 `model_<iter>.pt` 检查点 + `params/{env.yaml, agent.yaml}`。

**读日志（TensorBoard）：**

```bash
tensorboard --logdir logs/rsl_rl/lite3_velocity_walk
```

重点看 `mean_reward` / `track_*_velocity` 曲线，读法和第 2 篇 §8 一致。

## 4. 评估 / 回放 `play.py`

```bash
# 零动作 sanity check
python scripts/play.py Lite3-Walk-Flat --agent zero

# 加载最新检查点（无显示时默认 viser web，浏览器 http://localhost:8080）
python scripts/play.py Lite3-Walk-Flat

# 指定检查点
python scripts/play.py Lite3-Walk-Flat \
  --checkpoint-file logs/rsl_rl/lite3_velocity_walk/2026-xx-xx_xx-xx-xx/model_1999.pt
```

| 参数 | 说明 |
|---|---|
| `--agent zero/random/trained` | 零动作 / 随机 / 训练模型 |
| `--checkpoint-file <路径>` | 指定检查点（默认自动找最新） |
| `--viewer native/viser/auto` | 渲染后端；`viser` 网页，`native` 本地窗口 |
| `--no-terminations` | 关掉终止条件（观察动作更连贯） |

> `--agent zero/random` 不需要检查点，用来纯验环境；`trained` 需要能加载到 `model_*.pt`。

## 5. ONNX 导出与真机部署

训练完的检查点可一键导出 `policy.onnx`，供真机 C++ / onnxruntime 推理。这是 `VelocityOnPolicyRunner`（`src/tasks/velocity/rl/runner.py`）在 `save()` 里自动做的：

```python
class VelocityOnPolicyRunner(MjlabOnPolicyRunner):
  def save(self, path, infos=None):
    super().save(path, infos)
    ...
    self.export_policy_to_onnx(policy_path, "policy.onnx")
    attach_metadata_to_onnx(onnx_path, get_base_metadata(...))   # 附带观测/动作元信息
```

产物 `policy.onnx` + 元数据描述该策略的观测/动作，是「仿真 → 实机」最后一步。`src/assets/robots/lite3/config/joints.json` 定义了关节名 ↔ 电机 ID 的映射，配合部署（Mini2S 的 `description.json` / `joints.json` 同理）。

> 拿到 `policy.onnx` 之后怎么上真机：如何读元数据确定 53 维观测和 14 维动作的每个参数含义、如何用 `xgo_doglib` 标定并跑通闭环测试，见第 4 篇《真机部署测试》。

## 6. 进阶：tracking 脚手架（如何扩展新任务）

`src/tasks/tracking/` 是一套**未注册**的动作模仿（motion imitation）任务模板，结构完全镜像 velocity——`tracking_env_cfg.py` 有 `make_tracking_env_cfg()`，`mdp/` 有观测/奖励/终止，但 `config/__init__.py` 是空的（所以 `list_envs` 里没有 tracking 任务）。这正是「从模板扩展」的样板：

1. 在 `src/tasks/tracking/config/` 下建 `my_robot_track/`，写 env_cfg + rl_cfg + `__init__.py` register。
2. `make_tracking_env_cfg()` 产出的动作模仿任务用 `MotionCommandCfg`（命令来自 `.npz` 参考动作），奖励是各身体部位位置/朝向/速度的误差指数。
3. 训练时需 `--motion-file <动作.npz>`（`train.py` 里对 tracking 任务强制要求）。

对照第 1 篇「创建模板」的方法，就能往这个框架里加任何新任务。

## 7. 一个已知坑

`scripts/train_pipeline.sh` 里写了 `Lite3-Turn-Flat`，但项目里 **Lite3 只注册了 `Lite3-Walk-Flat`，没有 turn 任务**。直接跑该脚本会在前两个任务后报错；要么注释掉那行，要么参照 `mini2s_turn` 给 Lite3 补一个 turn 配置。

## 8. 总结

- 上真机三件套：**延迟（latency）+ 域随机化（dr events）+ ONNX 导出**。
- 训练靠 `train.py`，评估靠 `play.py --viewer viser`，读日志靠 TensorBoard。
- 扩展新任务 = 复制 velocity/tracking 的「三件套」+ register。
